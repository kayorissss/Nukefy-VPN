## 1. Что за проект (по факту, а не по README)

| Слой | Содержимое |
|---|---|
| Платформы | Android (Flutter + libbox sing-box 1.12 + VpnService), Windows (Flutter + sing-box.exe + xray.exe + zapret/winws) |
| Ядро | `sing-box` (TUN/локальный прокси), `Xray` только для XHTTP/SplitHTTP, `winws` для DPI-обхода |
| Архитектура | `provider` (ChangeNotifier) + сервисы-синглтоны + `utils`-парсеры |

Функционально это уже не «клиент подписки», а комбайн: VPN + zapret + Telegram WS Proxy + Karing-обход белых списков + тест скорости + диагностика + каталог дополнений + **музыкальный плеер с плейлистами и фоновым воспроизведением**. Последнее — главный вопрос к продуктовой гигиене (см. §4.6).

## 2. Сильные стороны (это правда хорошо)

1. **Инженерная дисциплина в опасных местах.** Загрузки проверяются по SHA-256 из GitHub release API (`tg_ws_proxy_service.dart:118-163`, `vpn_platform.dart:224-250`, `zapret_update_service.dart:47-73`), включая проверку размера и `https`-хоста. Это выше среднего для подобных проектов.
2. **Обновление Android защищено по-настоящему:** проверка package name, `longVersionCode` и **сверка подписи** `signingInfo.apkContentsSigners` (`MainActivity.kt:246-268`), установка через `FileProvider` + `ClipData`. Инсталлятор Windows — с `requireAdministrator` в манифесте, CI считает SHA-256 и умеет подписывать.
3. **Процессы запускаются списком аргументов, а не через shell.** Ни `Process.start('cmd', ...)`, ни склейки строк с пользовательским вводом (`zapret_service.dart:874` — свой токенайзер; `binPath` для `sc.exe`). Инъекции команд нет.
4. **Никакой самодеятельности с чужими программами.** `zapret_service.dart:89-97`: приложение владеет только своим именем службы `nukefy-zapret`, чужой `zapret` не трогает, а конфликт WinDivert показывает пользователю.
5. **Устойчивость к сбоям заложена в каркас:** `runZonedGuarded`, каждая ступень инициализации обёрнута в `guard()` с таймаутом и записью в `nukefy.log` (`main.dart:203-215`), окно показывается до тяжёлых операций, single-instance guard с восстановлением после неудачного restart.
6. **Хорошая доменная проработка:** эфемерные порты при занятых 10808/19090 на Windows с Hyper-V (`vpn_provider.dart:355-380`), правило `process_path` чтобы приложение не заворачивало свой же трафик в TUN (`singbox_config_builder.dart:199-208`), проверка «а трафик-то идёт» через локальный ingress, а не по факту «иконка горит» (`_verifyTraffic`).
7. **Комментарии объясняют причины,** а не пересказывают код («почему `allow_insecure`», «почему плитка стартует через unlockAndRun на MIUI»). Это редкость и большой плюс.

## 3. Найденные дефекты

Приоритеты: **P0** — ломает функцию/теряет данные, **P1** — безопасность/приватность, **P2** — качество и поддержка. Ничего не менял в коде — только фиксирую.

### P0-1. Статистика трафика молча не работает, если порт 19090 занят

`vpn_provider.dart:363` резервирует порт clash API с подстановкой свободного при занятости, конфиг sing-box/Xray берёт именно резолвнутый порт (`singbox_config_builder.dart:95`, `xray_config_builder.dart:145`), **а веб-сокет статистики всегда стучится в константу**:

```dart
// vpn_provider.dart:655
Uri.parse('ws://127.0.0.1:${AppConstants.clashApiPort}/traffic')  // всегда 19090
```

Ровно тот сценарий, ради которого писали подстановку портов (Windows + Hyper-V/NAT, второй экземпляр, чужой клиент на 19090), заканчивается «нулями» в «Статистике» и в тикере главной. Правка — одна строка: `final port = _ports?.clash ?? AppConstants.clashApiPort;` и подставлять её в URI (плюс перезапускать сокет после смены `_ports`).

### P0-2. `connect()` не имеет защиты от повторного входа и «залипает» в `connecting`

В `connect()` (`vpn_provider.dart:206-350`) `try` есть только вокруг `ensureRuleSets`. Всё остальное — запись `config.json`, `_platform.start()`, `buildJson` — не обёрнуто. Один сбойный `await` (а `File.writeAsString` на Windows легко падает, если файл держит антивирус или предыдущий процесс) оставляет UI в состоянии `VpnStatus.connecting` **навсегда**: кнопка крутится, «Отключить» вызывает `disconnect()` (он не отменяет уже идущий `connect`), а тот по завершении всё равно выставит `connected`. Повторный тап по кнопке запускает второй `connect()` параллельно первому.

Лечение: `bool _connecting` как мьютекс + `try/catch/finally` вокруг всего тела с переводом в `VpnStatus.error`, и токен сессии (`_attempt++`), которым `connect` проверяет, что его не отменили.

### P0-3. При ошибке чтения зашифрованного хранилища удаляется **весь** ваулт

```dart
// storage_service.dart:24-31
} catch (_) {
  await Hive.deleteBoxFromDisk(_boxName);   // подписки, серверы, настройки — всё
  _box = await Hive.openBox<String>(_boxName, ...);
}
```

Любая ошибка открытия — не только битый бокс, но и несовпадение ключа (восстановление из бэкапа, очистка `SharedPreferences`), блокировка файла другим процессом, антивирус — приводит к безвозвратному удалению всех серверов и настроек. Минимум: переименовать файл в `.corrupt-<дата>` перед удалением, отдельно отличать `HiveError` о неверном ключе и делать один повтор открытия.

### P0-4. Разъехавшаяся нумерация версий ломает автообновление

| Место | Значение |
|---|---|
| `pubspec.yaml:5` | `1.2.0+36` |
| `README.md:7` | «Текущий релиз: `1.1.0`» |
| `README.md:11` | «Что нового в **2.5.18**» |
| `app_constants.dart:8` | фолбэк `'2.5.8'` |
| `.github/workflows/release.yml` | дефолтный тег `v1.2.0` |

`VersionUtils.compare` честно сравнит `2.5.18 > 1.2.0`. Значит пользователь, у которого стоит старый `2.5.18`, **никогда не получит `1.2.0`** как обновление (`isNewer` вернёт `false`), а если GitHub отдаст в `/releases/latest` один из старых `2.5.x` — приложение предложит «обновиться» назад. Плюс README обещает 1.1.0. Нужен один источник истины (`pubspec`) и генерация README/фолбэка из него, а для перехода 2.5.x → 1.2.0 — разовый миграционный флаг «предложить обновление независимо от semver».

### P0-5. Автозапуск при загрузке Android ненадёжен

`BootReceiver.kt:22-27` поднимает **Activity** из бродкаста. Начиная с Android 10 фоновый запуск Activity из `BOOT_COMPLETED` блокируется; фолбэк — уведомление, но при неподтверждённом `POST_NOTIFICATIONS` (Android 13+) не покажется и оно. Для сценария «включить VPN после перезагрузки» правильнее `startForegroundService` прямо в `NukefyVpnService` с `ACTION_RESUME` (сессия уже сохранена в `last_config.json`), без UI вообще.

Плюс `NukefyVpnService.pending` — **одна статическая** ссылка на колбэк (`:323`, `:338`): если пользователь нажал «Подключить», а сервис умер/перезапустился, `MethodChannel.Result` не вызовется никогда — Dart-футура висит, UI в `connecting`.

### P0-6. Два ключа английской локализации отсутствуют

`noTrafficMode`, `trafficProbeUnavailable` есть только в `_ru` (`strings.dart:817-818`), используются в `notification_overlay.dart:328,338`. `S.t()` падает на `_ru`-фолбэк, поэтому **в английском интерфейсе эти две ошибки показываются по-русски**.

### P1-1. Секреты и ключ шифрования уезжают в облачный бэкап

В `AndroidManifest.xml` `<application>` (`:14-19`) **не задан `android:allowBackup`** → по умолчанию `true`. В бэкап попадают:
* `SharedPreferences` с `nkfy_vault_key` — **ключ AES** хранилища (`storage_service.dart:44-53`);
* сам Hive-бокс с подписками, серверами, паролями и UUID;
* `files/run/last_config.json` — полный конфиг sing-box с credentials (`NukefyVpnService.kt:265`).

То есть шифрование ваулта обходится тривиально: ключ лежит рядом и копируется тем же бэкапом. Фикс: `android:allowBackup="false"` + `android:dataExtractionRules`/`fullBackupContent` (исключить `nkfy_vault*`, `shared_prefs`, `run/`), а на Desktop — держать ключ в Windows Credential Manager / DPAPI вместо `SharedPreferences`.

### P1-2. Clash API без пароля

`singbox_config_builder.dart:338-342` и `xray_config_builder.dart:145`: `external_controller: 127.0.0.1:<port>`, `secret: ''`. Любой локальный процесс может читать статистику, переключать outbound, менять правила. Стоит генерировать случайный `secret` на сессию и передавать его в URI сокета. It не «дыра в интернет», но локальная атака бесплатна.

### P1-3. Обновление Windows-инсталлятора не проверяется по хэшу

`update_service.dart:123+` качает asset с GitHub и `vpn_platform.installUpdate()` **запускает его с правами администратора** без сверки. При этом релизный пайплайн публикует `SHA256SUMS.txt`, а tg-ws/zapret/xray — проверяются. Разнобой: самое опасное (exe под админом) — единственное без проверки. Android спасает проверка подписи, Windows — ничем. Нужно брать digest из release API (`asset['digest']`, как в `tg_ws_proxy_service.dart`) либо `SHA256SUMS.txt` и сверять до запуска.

### P1-4. «Дополнения» скачивают и запускают произвольный `.exe` без проверки

`addons_service.dart:208-275` берёт **первый** asset релиза (без выбора под платформу, без digest) и `:320` запускает найденный `.exe` через `ProcessMode.detached`. Каталог строится из всех репозиториев автора (`api.github.com/users/kayorissss/repos`), то есть компрометация любого из них = RCE на машине пользователя, у которого приложение и так запущено от админа. Минимум: требовать `digest` (как в tg-ws), фильтровать по имени под Windows, спрашивать подтверждение перед первым запуском.

### P1-5. `karingAllowInsecure = true` по умолчанию

`app_settings.dart:58`. Отключение проверки TLS-сертификата включено «из коробки» для Karing-профиля. Для обхода самоподписанных узлов это осмысленно, но дефолт должен быть `false` с явным предупреждением при включении (иначе весь трафик узла уязвим к MITM).

### P1-6. Лишние разрешения и `usesCleartextTraffic="true"`

* `android.permission.CAMERA` (`:11`) — сканер QR из приложения убран, в коде камеры нет (остались только строки `qr*` в `strings.dart`). Play-полиси требует обоснования для каждого «опасного» разрешения.
* `QUERY_ALL_PACKAGES` (`:12`) — нужно для сплит-туннелинга, но Google требует декларацию; на Android 11+ можно ограничиться `<queries>` для списка из `listApps`… (на практике для «всех приложений» разрешение всё же нужно — просто держите обоснование в репозитории).
* `usesCleartextTraffic="true"` (`:19`) — Dart-сеть этот флаг не соблюдает, а WebView в проекте нет; флаг просто расширяет поверхность. Убрать (если понадобится локальный HTTP-прокси — он идёт через свои сокеты и этого не требует).
* `REQUEST_INSTALL_PACKAGES` — обосновано самообновлением, ок.

### P1-7. Credentials в открытом виде на диске

`config.json`/`xray-config.json` (`vpn_platform.dart:421-422`, `xray` аналогично) и `last_config.json` пишутся плейн-текстом, хотя подписки лежат в AES-боксе. На Android это app-private, но с учётом P1-1 — уезжает в бэкап; на Windows папка `%APPDATA%` читается любым процессом пользователя. Как минимум — не держать `secret`/`password` в файле дольше жизни процесса и чистить при disconnect.

## 4. Качество, архитектура, поддержка (P2)

**4.1. Отключённые линты.** `analysis_options.yaml`: `avoid_print: false`, `use_build_context_synchronously: false`. Второе — самое частое место реальных крашей Flutter (`context` после `await`). Разумнее точечно `// ignore` там, где действительно нужно, а правило вернуть.

**4.2. Глобальное изменяемое состояние.** `SubscriptionService.sendHwid` / `clientIdentity` — статические поля, которые «зеркалит» `SettingsProvider._mirror()`; сервисы-синглтоны (`ZapretService.instance`, `TgWsProxyService.instance`, `AddonsService.instance`, `StorageService.instance`) и статический `NukefyCore.box`. Это делает почти невозможным юнит-тестирование логики подключения и подписок без живого окружения.

**4.3. Дупликация в `connect()`.** Блок сборки конфига и запуска повторён дважды (обычный и «эфемерные порты») — 40 строк копипасты, которые уже начали расходиться (`_ports` присваивается в разных ветках). Вынести в `Future<CoreStartResult> _startWith(SingboxConfigBuilder..., LocalPorts)`.

**4.4. Тестов почти нет на самом рискованном.** 29 тестов на парсеры, xray-конфиг, zapret-аргументы и утилиты. Ноль тестов на `VpnProvider` (жизненный цикл, порты, отмена), `StorageService` (миграция/сбой ключа), `UpdateService`, `AddonsService`, `SubscriptionService` (HWID, зеркала). С учётом P0-2 и P0-3 — это именно те места, где тесты окупаются сразу.

**4.5. Своя l10n вместо `intl`.** `lib/l10n/strings.dart` — 897 ключей в двух картах, `S.t(key)` с фолбэком. Нет проверки на пропуски (см. P0-6), нет плюрализации («1 минуту»/«5 минут»), нет инструментов извлечения. Для проекта такого размера ARB + `flutter gen-l10n` дал бы компиляционную защиту от опечаток в ключах (сейчас `s.t('typoKey')` просто покажет `typoKey`).

**4.6. Музыкальный плеер внутри VPN-клиента.** `music_service` 561 строка + `music_audio_handler` + `music_visualizer` + `audio_service`/`just_audio`/`audioplayers`/`audio_metadata_reader` в зависимостях, при том что README позиционирует продукт как VPN. Это +4 плагина, +foreground-сервис `mediaPlayback` в манифесте, +экспортированный `MediaBrowserService`, и постоянный источник регрессий в релизных заметках. Предложение: вынести в отдельное приложение/ветку или закрыть флагом сборки — это заметно упростит и APK, и аудит.

**4.7. Производительность.** Тикер `VpnProvider` раз в секунду вызывает `notifyListeners()` у провайдера, на который подписаны почти все экраны (`home_screen.dart:37-41`) — каждую секунду перестраиваются десятки виджетов, даже когда изменился только счётчик времени. Лучше отдельный `ValueNotifier<Duration>`/`ChangeNotifier` только для таймера и трафика. Плюс `_MaximizeGuard.start()` (`main.dart:392`) крутит `Timer.periodic` 2 с бесконечно, в том числе в трее.

**4.8. `AppLog` пишет через `debugPrint` каждую строку** (`app_log.dart:27`) — на релизной сборке это не бесплатно и дублирует файл. Стоит оставить `debugPrint` только в `kDebugMode`.

**4.9. Mутный дефолт MTU.** `AppConstants.defaultMtu = 9000` при слайдере 1280–9000 (`settings_screen.dart:310-315`). 9000 на TUN — редкость и источник фрагментации/「часть сайтов не открывается」 на мобильных сетях; безопасный дефолт — 1500 (Android) / 1400–1500 (Windows).

**4.10. Документация.** `README.md` — 40 KB changelog, текущая версия в шапке неверна (P0-4). Нет `LICENSE` (для публичного репозитория это юридически «все права защищены» — контрибьюторам и форкам неясно, что можно), нет `CHANGELOG.md` (changelog живёт в README и `tool/release_notes.md` в трёх форматах), нет `CONTRIBUTING.md`.

**4.11. Мелочи, замеченные попутно.**
* `--tray` записывается в задачу планировщика (`vpn_platform.dart:961`), но нигде не читается — «старт в трее» работает только через настройку.
* `BootReceiver.readFlag` парсит JSON подстрокой `"\"$key\":true"` — сломается от любого пробела в форматировании; лучше `JSONObject`/`jsonDecode`.
* `installApk` возвращает `"version"`, если версия не новее — правильный отказ, но Dart-обёртка маппит его в `ApkInstallResult.notNewer`; UI должен явно объяснять, что это не ошибка.
* `checkConflicts()` вызывает `tasklist` перед каждым подключением — на слабых машинах это сотни мс в горячем пути; можно кэшировать и вызывать при старте/смене конфигурации.
* Пустые каталоги `design/` (PNG 1.1 МБ) и `assets/rkntyan.png` — стоит проверить, используются ли (иначе −1 МБ из бандла).

## 6. Чего я не проверял (и почему)

* **`flutter analyze` / `flutter test` не запускались** — в песочнице нет Flutter SDK, а сеть доступна только к github.com/pub.dev/registry.npmjs.org (SDK тянется с `storage.googleapis.com`). Все выводы — из чтения кода, статически.
* **Сборка Android не проверялась:** требует `android/app/libs/libbox.aar` (собирается в CI из sing-box 1.12 + NDK), `.gitignore` его исключает.
* **Рантайм не проверялся:** TUN, WinDivert, реальные подписки, установка APK/инсталлятора — только по коду.
* **Сторонние бинарники** (`winws.exe`, `sing-box.exe`, `xray.exe`) не аудировались — они поставляются официальными релизами и проверяются хэшами в CI.

Если нужно, могу сразу оформить пункты 1–4 и 8 из таблицы как отдельный PR с тестами — это компактно и не затрагивает продуктовые решения.
